# ERPV2 v1.6 使用者 Browser Manual Smoke 清單

日期：2026-07-29

狀態：等待使用者實測

目的：以實際日常操作確認 v1.6 文案精簡後仍清楚、安靜且不誤導。這份
manual smoke 不重複工程自動化；重點是主觀資訊層級、真實裝置、
Safari／VoiceOver 與操作理解。

## 測試前

- 請使用可安全新增／修改／刪除測試資料的環境，不要在正式資料上測試
  不可逆操作。
- 本次 runtime 基準為 `35e1669`；請在目前最新 main（清單 commit
  `65ff489` 或後續 closure）重新 build／重啟前端後測試。回報時附上
  `git rev-parse --short HEAD`，不要使用舊 dist 或未重啟的 dev server。
- 建議至少準備一組 admin；manager／sales 請使用既有專用測試帳號，或只在
  可整庫重置的測試資料庫新建專用帳號，不要重設真實員工密碼。自建帳號
  應避免產生車輛、收支或薪資關聯，以便測後刪除。
- Desktop 建議 Chrome；Mobile 請優先使用真實 iPhone Safari。
- 登入錯誤抽查每個裝置／主題只需刻意失敗一次；同帳號與同 IP 在 60 秒內
  不要連續失敗 5 次以上。若出現「登入嘗試次數過多」，請停止重試並等待
  limiter 到期（帳號加 IP 約 1 分鐘；大量重複帳號嘗試可能最長約 15 分鐘），
  這是既有安全機制，不是 v1.6 文案缺陷。
- 每個項目記錄 `通過`、`失敗`、`受阻` 或 `未測`。失敗時請附頁面、
  角色、裝置、操作步驟、實際結果與預期結果；截圖可輔助，但不取代描述。

## A. Desktop Chrome

### A1. 登入

- [ ] 刪除重複副標後仍能理解登入用途；登入失敗時容易找到錯誤、回到欄位
  修正並重送。

### A2. Dashboard

- [ ] 工作概況只呈現數字與必要狀態，沒有重複解釋卡片名稱。
- [ ] 經營概況能理解「完整月份」、收入／支出日期、成交日期、
  approved-only 與正式現金帳面餘額。
- [ ] 近 30 天成交量、毛利、現金變化的名稱、期間、單位與口徑清楚。
- [ ] KPI Card 高度與兩列節奏可接受；「含保留中」不造成突兀跳動。
- [ ] 整體比 v1.5 簡潔，沒有「操作說明書感」。

### A3. 常用車輛流程

以下完整流程會建立不可回復的正式紀錄：車輛成交後無法刪除，車輛流程
收支無法由一般收支功能刪除，並會影響資金帳戶餘額、Dashboard 統計與
成交月份的薪資草稿。只有可在測後整庫重置的測試資料庫才能實際走完整
流程；否則只檢視既有 sold 車輛與既有流程畫面，不要新增／核准假收支或
執行成交結案，無法安全驗證的項目填 `未測`。

- [ ] 車輛列表刪除副標後用途仍清楚；可分辨「此頁沒有資料」、
  「尚無符合條件的車輛」與「目前沒有在庫車輛」，並理解回第 1 頁或清除
  篩選條件的下一步。可在列表 URL 加 `?page=999` 唯讀觀察「此頁沒有資料」
  與回第 1 頁；全空狀態只能在可整庫重置的測試資料庫觀察，否則該子項填
  `未測`。
- [ ] 新增車輛：欄位、required、同步購車付款與錯誤都能理解。
- [ ] 整備完成並上架：開價、底價、日期、銷售備註用途清楚。
- [ ] 收訂金並保留：買方搜尋、成交價、訂金、賣車人、帳戶清楚。
- [ ] CustomerSelect 有結果時第一次 Escape 只收搜尋清單，第二次才關 Modal。
- [ ] CustomerSelect 空白時 Escape 可直接關 Modal，焦點返回原按鈕。
- [ ] 收尾款：金額、帳戶與備註清楚。
- [ ] 成交結案：能理解成交日期決定薪資月份，收款日期不影響成交月份。
- [ ] admin 開啟「補登／修正收購價」Modal 後不要送出，以「關閉」或 Escape
  離開；能理解收購價影響單車毛利與薪資獎金、薪資月份確認或發薪後不可
  修改。獎金歸屬已鎖定時按鈕不出現的原因可由鎖定提示理解；沒有已鎖定
  車輛請將該子項填 `未測`。
- [ ] 在可安全開啟的車輛流程 Modal 內以 Tab／Shift+Tab 循環，焦點不離開
  Modal，且能抵達目前可用的欄位、關閉與送出控制。保持欄位原值／空白，
  不要輸入、不要在欄位內按 Enter、不要按送出；收購價必填未完成時送出鈕
  disabled、不在 Tab 順序屬預期。沒有 preparing／listed／reserved 車輛可
  安全開啟時填 `未測`。
- [ ] 上報單車支出：admin 的正式支出與 manager／sales 的待審核後果清楚。
- [ ] Modal 送出中按 Escape 的現行行為可接受；若覺得容易誤觸，請回報。

### A4. 收支、客戶與員工

admin 建立的一般收支送出後即為 approved，不能修改或刪除；既有 pending
收支一經核准或駁回也不可逆，核准後會計入正式餘額、車輛毛利與薪資草稿。
只有可整庫重置的測試資料庫才能實際新增、核准或駁回；否則只檢視既有
pending／approved／rejected 資料，無法安全驗證的項目填 `未測`。

- [ ] 收支列表刪除副標後用途仍清楚；可分辨「此頁沒有資料」、
  「尚無符合條件的收支紀錄」與「尚無收支紀錄」，Filter chip 與回第 1 頁／
  清除篩選條件的下一步清楚。可在列表 URL 加 `?page=999` 唯讀觀察
  「此頁沒有資料」與回第 1 頁；全空狀態只能在可整庫重置的測試資料庫
  觀察，否則該子項填 `未測`。
- [ ] 新增一般收支：用途說明足夠，送出多欄錯誤後第一個錯誤容易發現並修正。
- [ ] 收支核准／駁回：pending、approved、rejected 與正式彙總關係不誤導。
- [ ] 客戶建立、搜尋、無結果與搜尋失敗不會互相混淆；只建立未綁定車輛的
  測試客戶並於測後刪除，若已綁定車輛而無法刪除，請回報並保留。
- [ ] 員工建立、編輯與角色用途清楚；停用只使用可恢復的測試帳號並在測後
  還原。不要刪除既有真實帳號；smoke 期間自建且無任何業務關聯的測試
  帳號應在測後刪除，若因已有關聯而無法刪除，請改為停用並回報。
- [ ] 只對可恢復的測試帳號重設密碼，不要重設真實員工帳號；重設後能理解
  既有 Session 失效、需重新登入並修改密碼。
- [ ] 管理員本人不可變更角色／停用／刪除的原因不用 hover 也看得到。

### A5. 帳號、薪資與列印

- [ ] 我的帳號：username／Email 登入關係、清除 username 後果與改密碼清楚。
- [ ] 改密碼成功、Session 失效與重新登入後果清楚。
- [ ] 薪資月份列表刪除副標後用途仍清楚；有既有月份時容易進入檢視，
  無資料時「尚未建立薪資月份，請選擇月份並建立草稿」的下一步不誤導，
  且載入失敗不會被誤認為空清單。不要為了 smoke 建立草稿。
- [ ] 薪資 draft：只檢視既有草稿的預覽、重算與「本月未結束不能確認」
  warning。薪資草稿建立後無法刪除，只能在可整庫重置的測試資料庫建立；
  沒有既有草稿請填 `未測`。
- [ ] 薪資 confirmed／paid：只檢視既有月份的鎖定、發薪日期、帳戶與唯讀
  文案。本系統沒有取消確認或退回發薪；不要為了 smoke 真的確認或發薪，
  沒有既有資料請填 `未測`。
- [ ] 獎金方案：各檢視一個未使用與已使用方案；已使用方案能理解規則已鎖定、
  變更需建立新版本。不要為 smoke 新增或套用正式方案；沒有對應的未使用或
  已使用方案，請將該子項填 `未測`。
- [ ] 員工薪資設定：只檢視、不實際儲存；能理解變更只影響未確認月份，
  不會改寫已鎖定快照。
- [ ] 待補獎金歸屬：只檢視既有清單與提示，不要實際儲存。歸屬存入後車輛
  會離開待補清單且畫面無法改回，只有可整庫重置的測試資料庫才能送出；
  能理解補齊後需回薪資月份重算，沒有待補資料請填 `未測`。
- [ ] 在薪資加扣項 Modal 內以 Tab／Shift+Tab 循環，焦點不離開 Modal，且能
  抵達所有可用欄位與「取消」。沒有既有 draft 請填 `未測`；「新增」因必填
  未完成而 disabled、不在 Tab 順序屬預期，可填測試值啟用後只檢查焦點，
  不要按下「新增」。
- [ ] 資金帳戶：只檢視建立／編輯欄位、啟用／停用與刪除確認文案，不實際
  送出。期初餘額與類型會直接改變 Dashboard 現金帳面餘額與資金帳戶
  餘額；只有可整庫重置的測試資料庫才能實際建立或修改，否則填 `未測`。
- [ ] 稽核紀錄：篩選、有結果、無結果與「清除篩選條件」的下一步清楚。
- [ ] 使用安全測試帳號觸發強制改密碼時，至少 8 字元、不可與目前密碼相同、
  修改後繼續登入等提示清楚。
- [ ] 車輛建檔與成交結案列印／PDF 預覽可讀，沒有裁切、重疊或錯頁。

## B. 角色抽查

manager／sales 抽查以既有畫面、入口與文案理解為主；這兩種角色建立的
收支會進入 pending，車輛流程／快捷收支無法刪除，後續核准或駁回也不可逆。
只有可整庫重置的測試資料庫才能實際送出，否則只檢視並將無法安全驗證的
項目填 `未測`。

### B1. Manager

- [ ] Dashboard 財務 KPI 可理解。
- [ ] 車輛、收支、客戶流程與後果可理解。
- [ ] 不會看到員工／帳號、薪資、Audit 等 admin-only 入口或教學。

### B2. Sales

- [ ] Dashboard 不顯示財務 KPI 或 approved-only 財務教學。
- [ ] 車輛、客戶與銷售收款流程可理解。
- [ ] 不會看到收購價、完整成本或單車毛利。

## C. 真實 iPhone Safari

- [ ] Dashboard、Vehicle、MoneyEntry、Customer、User、Cash Account、
  Salary 主要頁面沒有整頁水平捲動。
- [ ] Header 與主要 action 不擁擠；刪除副標後沒有突兀大空白。
- [ ] 長 warning 只在需要時顯示，換行後仍容易閱讀。
- [ ] Form label／error 不被截斷，鍵盤彈出後仍能找到第一個錯誤。
- [ ] 登入或表單送出失敗時，焦點移到錯誤訊息且軟鍵盤收起後，仍能順暢

- [ ] 員工／資金帳戶表格可在自己的區域橫向捲動，不拖動整頁。
- [ ] Modal／Filter Drawer 可開關、捲動與操作；關閉後焦點回到原按鈕。
- [ ] 瀏海與 Home Indicator Safe Area 正常，底部按鈕不被遮住。
- [ ] Mobile 畫面文字高度相較 v1.5 明顯下降，但沒有刪掉關鍵資訊。

## D. VoiceOver 抽查

- [ ] 登入錯誤只朗讀一次，且能理解是帳號或密碼錯誤。
- [ ] 新增收支多欄錯誤時，第一個錯誤欄位名稱與錯誤只朗讀一次。
- [ ] 資金帳戶「帳戶名稱」能被正確朗讀。
- [ ] Vehicle workflow Modal 有可理解的 dialog 名稱，欄位名稱清楚。
- [ ] Escape／關閉後 VoiceOver 焦點回到開啟 Modal 的按鈕。

## E. 最終主觀判斷

- [ ] 沒有因刪字而不知道按鈕用途。
- [ ] 沒有因刪字而不知道不可操作原因。
- [ ] 重要 warning／error 比一般文字更容易辨識。
- [ ] 切換 light／dark 後，warning、error、success 與 disabled 狀態仍明顯
  有別於一般文字；至少抽查登入錯誤、新增收支欄位錯誤、薪資 draft warning
  與 confirmed 鎖定提示，無對應既有資料則註明 `未測`。
- [ ] 日常畫面沒有操作說明書感。
- [ ] 沒有希望恢復的關鍵資訊。
