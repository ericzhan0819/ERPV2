## 正式契約

### 個人資料

- 顯示名稱與 username 可修改；Email 與角色只讀呈現，不會送進 self profile payload。
- Username 留白會明確送出 `null`；非空輸入在送出前 trim 並轉小寫，成功後以後端完整 `UserResource` 回填。
- 畫面說明 3～30 字元、允許字元與小寫正規化；null username 會明確提示仍可使用 Email 登入。
- 後端 `422` 的 `name`／`username` 錯誤只回到對應欄位；其他錯誤顯示安全 fallback。
- 更新成功後 Auth Context 與 Header 名稱立即同步，不需 reload。

### 密碼

- 目前密碼、新密碼與確認新密碼只送至既有 `PATCH /api/me/password`。
- 密碼表單與個人資料分開提交；confirmation 明確不一致時先在前端阻擋，後端 current password／password／confirmation 錯誤仍回到各自欄位。
- 送出期間欄位與按鈕 disabled，並以狀態鎖阻擋重複 submit。
- 成功後三個密碼欄位全部清空，顯示成功訊息，並沿用 Auth Context 的 Session generation rotation。
- API 已完成但 Context 已切換時，沿用第 10 部分契約導向 Login 並提示使用新密碼；HTTP 401 導回 Login。

### Accessibility／RWD

- 所有可編輯欄位都有 visible label；required、說明與 per-field error 使用原生屬性及 `aria-describedby` 關聯。
- Header 入口、Theme Toggle、登出與表單按鈕維持至少 44px 操作高度及可見 `focus-visible`。
- Account 內容在 Mobile 單欄，`lg` 起才將兩個表單並排；長 Email 使用可換行呈現。
- Theme Toggle 保留在 Header；Account 頁不建立 Theme 偏好、Avatar、通知或 Session 管理。
