## 2. 原始問題

ERPV2 同時可能從不同入口使用：

- LAN：例如 `192.168.0.40`
- Tailscale：例如 `100.112.1.114`

前端 API 會依目前頁面的 hostname 連到同一台主機的 `:8000`，但 local public disk 原本完全依 `APP_URL` 產生圖片絕對網址。當 `APP_URL` 固定為 Tailscale IP，而手機從 LAN IP 進入時，API 可用，圖片網址卻仍指向另一個 IP，因此車輛列表封面與詳情照片無法載入。

## 3. 最終契約

### 3.1 內部後台照片

只有以下內部 Resource 明確 opt-in 跟隨 request origin：

- `VehicleCoverPhotoResource`
- `VehiclePhotoResource`

local disk 圖片網址使用經 trusted-proxy 判定後的實際 API request：

```text
scheme + host + port + /storage/path
```

因此：

- 從 LAN HTTP 入口呼叫，圖片跟隨 LAN HTTP origin。
- 從 Tailscale HTTP 入口呼叫，圖片跟隨 Tailscale HTTP origin。
- 從可信任反向代理的 HTTPS 入口呼叫，圖片使用 HTTPS，不產生 mixed content。
- S3／Cloudflare R2 等非 local disk 維持 Storage driver 產生的 CDN／物件儲存網址。

### 3.2 公開官網照片

`PublicVehiclePhotoResource` 維持原本契約，直接使用：

```php
Storage::disk($disk)->url($path)
```

公開 API 圖片不跟隨 API 呼叫端 host，固定使用：

- local disk 的 `APP_URL` canonical 絕對網址；或
- S3／R2 的 CDN 網址。

這確保 Next.js Server Components、SSR、ISR 與 `og:image` 不會把 `localhost`、container name 或內網 IP 烘進公開快取輸出。

## 4. Proxy 與 Host 安全

新增：

- `backend/app/Support/TrustedHostPatterns.php`
- `backend/config/trustedhosts.php`
- `backend/config/trustedproxy.php`
- `TRUSTED_HOSTS`／`TRUSTED_PROXIES` 環境設定
- `bootstrap/app.php` 的明確 `trustHosts(at: ..., subdomains: false)`
- `AppServiceProvider` 以 `TrustProxies::at()`／`withHeaders()` 顯式綁定 proxy 設定

規則：

- 非 `local` 且非 PHPUnit 環境才會啟用 Laravel `TrustHosts` middleware。
- `APP_URL` host 自動列入 trusted hosts。
- `TRUSTED_HOSTS` 只補充 LAN、Tailscale、`localhost` health check 或 IP probe 等額外入口；不含 port，禁止萬用字元。
- host patterns 採精確比對，不自動信任子網域；未列入的 raw `Host` 會回 400。
- `TRUSTED_PROXIES` 只允許明確 IP／CIDR，預設 `127.0.0.1,::1`，禁止設定為 `*`。
- Proxy IP 與 header mask 由 `AppServiceProvider` 顯式設定，不依賴 `TrustProxies` 的 legacy config fallback。
- 只接受可信 proxy 的 `X-Forwarded-For`、`X-Forwarded-Port`、`X-Forwarded-Proto`。
- 刻意不信任 `X-Forwarded-Host`，避免外部 header 改寫正式 host。
- `APP_ENV=local` 時 raw `Host` 不受 `TrustHosts` 保護；此限制已在 README 明示，不以 local curl 假裝 production 驗證已啟用。

正式部署時，Nginx／Caddy 必須保留允許的 `Host`，並正確覆寫 `X-Forwarded-Proto` 與 `X-Forwarded-Port`。同時保留 LAN／Tailscale 或 `localhost` health check 時，必須逐一寫入 `TRUSTED_HOSTS`。

## 5. Review findings 處理

### Finding 1：Public API 違反 SSR／ISR 契約

已修正：

- request-origin 改寫只限內部 Resource 明確 opt-in。
- `PublicVehiclePhotoResource` 恢復直接使用 Storage canonical URL。
- 新增 public feature test，使用不同 SSR caller host 呼叫 API，驗證圖片仍固定為 canonical HTTPS URL。

### Finding 2：HTTPS 反向代理可能產生 HTTP 圖片

已修正：

- 加入明確 trusted proxy 設定。
- 內部圖片使用經 proxy middleware 判定後的 `getSchemeAndHttpHost()`。
- feature test 驗證可信 loopback proxy 可產生 HTTPS 圖片 URL。
- feature test 驗證不可信來源無法偽造 `X-Forwarded-Proto`。

### Finding 3：Resource 沒有可失敗的回歸測試

已修正：

- 使用絕對 URL 呼叫內部車輛列表，驗證封面 URL 跟隨 LAN request origin。
- 使用絕對 URL 呼叫內部照片清單，驗證原圖與縮圖都跟隨 LAN request origin。
- 使用不同 SSR caller host 呼叫公開 API，反向驗證 public URL 不跟隨 request host。
- 直接 revert 任一內部 Resource 回 `Storage::url()`，新增 feature test 會失敗。

### Finding 4：Host header 反射

已處理：

- 公開 API 不再反射 request host。
- trusted proxy 不接受 `X-Forwarded-Host`。
- 非 `local`／非測試環境以 `APP_URL + TRUSTED_HOSTS` 精確白名單驗證 raw `Host`。
- 內部 request-origin 圖片只會反射已列入白名單的 host。
- `local` 環境因 Laravel 框架設計不啟用 `TrustHosts`，文件已明確揭露此邊界。

### Finding 5：production 單一 APP_URL host 會封鎖 LAN 與 health check

已修正：

- `trustHosts()` 改為明確 callback，不再只接受 `APP_URL` 單一 host。
- `APP_URL` host 自動列入，額外入口由 `TRUSTED_HOSTS` 逐一補充。
- 預設額外允許 `localhost`、`127.0.0.1`、`::1`，保留本機 health check。
- LAN／Tailscale 範例已加入 `.env.example`。
- `subdomains: false`，避免因 canonical domain 自動放行未知子網域。

### Finding 6：TrustHosts 在 local／tests 為 no-op 且原本零覆蓋

已修正測試與文件：

- `TrustedHostPatternsTest` 直接檢查 bootstrap 實際註冊的 `TrustHosts::hosts()`，刪除或退回無參數 `trustHosts()` 時會失敗。
- 使用 `Request::setTrustedHosts()` 繞過 Laravel 的測試環境短路，驗證 canonical、LAN、Tailscale、IPv4／IPv6 health check 可通過。
- 反向驗證未列 host 與未明示子網域會拋出 `SuspiciousOperationException`。
- README 明確寫出 `APP_ENV=local` 與 PHPUnit 不啟用 trusted-host middleware，local raw Host 仍未經這項驗證。

### Round 3 Finding：trustProxies 依賴 legacy config fallback

已修正：

- reviewer 建議的 `at: fn () => config(...)` 在目前 Laravel 版本不可用，因為 `trustProxies()` 的 `at` 只接受 `array|string|null`。
- 直接在 `bootstrap/app.php` 呼叫 `config()` 也不可行，該 callback 執行時 config repository 尚未綁定。
- 最終改由 `AppServiceProvider::boot()` 在 config 已載入後明確呼叫 `TrustProxies::at(config('trustedproxy.proxies'))` 與 `TrustProxies::withHeaders(...)`。
- 新增反射斷言，直接檢查 framework static proxy IP 與 header mask 已被 provider 設定；移除 provider 綁定時，即使 legacy fallback 尚在，測試仍會失敗。
- `AppServiceProvider::boot()` 與 `config/trustedproxy.php` 已補註解，明確記錄 `trustProxies()` 不接受 Closure、`withMiddleware()` 階段 config 尚未載入，因此不得搬回 bootstrap。
- wiring test 除了驗證顯式綁定，也要求 proxy 清單不得為空、不得包含 `*`，避免只做 config 與 static 值的同義互比。

### Round 5 Finding：wiring test 受外部 TRUSTED_PROXIES 影響

已修正：

- `phpunit.xml` 明確固定 `TRUSTED_PROXIES=127.0.0.1,::1`，避免開發者 `.env` 或 shell process 改變回歸結果。
- PHPUnit 的 `<env force="true">` 只覆寫 `getenv()` 與 `$_ENV`；Laravel Dotenv repository 會優先讀 `$_SERVER`，因此同步加入 `<server force="true">` 才能真正隔離 `TRUSTED_PROXIES=` 的外部空值。
- 已用 reviewer 的重現指令驗證：`TRUSTED_PROXIES= ./vendor/bin/phpunit --filter test_app_provider_explicitly_binds_trusted_proxies_and_headers` 通過，1 test／5 assertions。
- `assertNotContains('*', $trustedProxies, true)` 已移除錯誤的第三參數；PHPUnit 12 的第三參數是 failure message，不是 strict flag。

接受的 Low 邊界：

- `TRUSTED_HOSTS` 萬用字元會被視為字面字串並 fail-closed；README 與 `.env.example` 已禁止萬用字元，不新增額外 parser。
- `APP_URL` 與額外 hosts 同時完全無法解析時會產生空 pattern list；這代表部署設定本身已損壞，維持已知低機率邊界，不擴張 hotfix。

### 7.5 Production-mode trusted-host smoke

以臨時 Laravel server 啟動：

```text
APP_ENV=production
APP_URL=http://100.112.1.114:18080
TRUSTED_HOSTS=localhost,127.0.0.1,::1,192.168.0.40
```

實際呼叫 `/up`：

```text
Host: 100.112.1.114:18080  → HTTP 200
Host: 192.168.0.40:18080   → HTTP 200
Host: localhost:18080      → HTTP 200
Host: evil.example.com     → HTTP 400
```

此測試直接驗證 production 環境下 canonical、LAN 與 health check Host 可用，未列 Host 會被拒絕；不只依賴 Symfony 單元模擬。

另以顯式 proxy 設定啟動：

```text
APP_ENV=production
APP_URL=http://api.erp.example.com:18081
TRUSTED_HOSTS=api.erp.example.com,localhost,127.0.0.1
TRUSTED_PROXIES=127.0.0.1,::1
```

實際呼叫公開 API：

```text
Host: api.erp.example.com:18081
X-Forwarded-Proto: https
links.first → https://api.erp.example.com:18081/api/public/vehicles?page=1
```

這證明 `AppServiceProvider` 的顯式 `TrustProxies::at()` 綁定在 production request 上生效，不再依賴 framework legacy fallback。
