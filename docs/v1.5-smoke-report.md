## 4. 第 16 部分最終審查與 Claude follow-up

- Password：Request 只將密碼傳入 Auth／Hash 流程；`UserResource` 不含密碼；User model hidden；Audit model event 會剔除 `password`，authentication audit 不保存原始 login；未發現將密碼值寫入一般 log 的程式。
- Alias limiter：可解析的 username／Email 都以 `uid:<id>` 作為 canonical identity，共用 account 與 identifier + IP limiter；正反順序、大小寫、成功清除與不存在識別均有回歸測試。
- Middleware：authenticated 營運 routes 預設套用 `active` 與 `password.changed`；只有 `/api/me`、self profile、self password 明確排除；route coverage test 防止新增路由漏掛。
- Self endpoint：profile／password FormRequest 對 Email、role、is_admin、is_active 與其他管理欄位採 `missing` 拒絕，不會靜默忽略。
- App config：只有 source-controlled `frontend/src/config/app.ts`，沒有 settings table、API 或線上設定頁。
- 範圍：第 16 部分文件同步本身未新增 schema、dependency 或無關 UI 重構，未修改 v1.1～v1.4 PLAN。

初次 Codex 審查未發現阻擋問題。後續 Claude adversarial review 判定整體通過，另提出
4 個低嚴重度項目；Codex 回到實際程式與測試查證後處理如下：

1. 有效：停用帳號輸入正確密碼時，原本會在 active 檢查前清除 identifier + IP 與
   canonical account limiter。修正為只有 active 正式登入才清除；停用分支保留已記入的
   兩層嘗試並增加 IP-wide failure。回歸測試確認第五次停用帳號正確密碼嘗試後三層計數
   皆保留，下一次 alias 嘗試回 `429`。
2. 有效：`409 PASSWORD_CHANGE_REQUIRED` event 原本未攜帶 request generation。修正後每個
   409 從 Axios config 取出 stamped generation，Context 只接受與目前 generation 相同的
   通知；未追蹤或舊 Session 回應不再把新登入者導向強制頁。
3. 有效：self profile 已在後端提交、但前端 Auth Context 已切換時，原本會落入通用失敗
   訊息。修正為辨識 committed-stale response，導向 Login 並顯示「個人資料已更新，請
   重新登入確認」，不再誤報資料庫寫入失敗。
4. 不在 v1.5 規格範圍：`PATCH /api/me/password` 額外 per-user throttle。此項是新的 429
   門檻、key 與成功請求計數契約，不是既有實作違反；未經產品決策不直接擴張。若後續要
   採用，應先在新 hotfix PLAN 明確定義門檻、回應與測試。

Claude 另實測 Laravel 13 `SessionGuard::attempt()` 的 Timebox，存在與不存在帳號皆約
200ms，否定登入 timing oracle 疑慮，因此不列 finding。
