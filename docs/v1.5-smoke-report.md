## 4. 第 16 部分最終審查

- Password：Request 只將密碼傳入 Auth／Hash 流程；`UserResource` 不含密碼；User model hidden；Audit model event 會剔除 `password`，authentication audit 不保存原始 login；未發現將密碼值寫入一般 log 的程式。
- Alias limiter：可解析的 username／Email 都以 `uid:<id>` 作為 canonical identity，共用 account 與 identifier + IP limiter；正反順序、大小寫、成功清除與不存在識別均有回歸測試。
- Middleware：authenticated 營運 routes 預設套用 `active` 與 `password.changed`；只有 `/api/me`、self profile、self password 明確排除；route coverage test 防止新增路由漏掛。
- Self endpoint：profile／password FormRequest 對 Email、role、is_admin、is_active 與其他管理欄位採 `missing` 拒絕，不會靜默忽略。
- App config：只有 source-controlled `frontend/src/config/app.ts`，沒有 settings table、API 或線上設定頁。
- 範圍：第 16 部分只修改文件與 PLAN；未新增 schema、dependency、runtime 或 UI 重構，未修改 v1.1～v1.4 PLAN。

審查結果：沒有可重現 finding。
