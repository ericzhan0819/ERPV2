## Browser finding 與修正

1. Vehicle workflow Modal 與 Salary adjustment Modal 缺少 dialog semantics、
   Escape、Tab containment、body scroll lock 與 trigger focus return。
   新增共用 `useDialogFocus`，並補 component tests。
2. `FormAlert` 同時使用 assertive live region 與主動 focus，在 Orca 會重複
   朗讀。主動 focus 模式改為 `aria-live="off"`；被動錯誤仍維持 assertive。
3. 資金帳戶 sibling visible labels 沒有程式化關聯。建立／編輯欄位補上
   `htmlFor`／`id`，並新增 accessible-name 回歸測試。
4. MoneyEntry 首錯立即 focus 時，Orca 會重複朗讀 description。延後 100ms
   聚焦，讓 AT-SPI 關聯先穩定；Vitest 與真實 Orca 均通過。
5. Claude High 發現 `CustomerSelect` 展開時按 Escape 會冒泡至新增的
   dialog listener，連帶關閉「收訂金並保留」並遺失已填資料。
   `useDialogFocus` 現在尊重 child handler 的 `defaultPrevented`；回歸測試
   確認第一次 Escape 只收起 customer listbox，第二次才關閉 Modal 並將
   focus 返回 trigger。
6. 同輪審查指出新納入 focus trap 的 Vehicle workflow Modal 仍有 sibling
   labels。`Field`、`CashAccountField` 與 Reserve／FinalPayment／Expense
   的直接欄位已補原生關聯並用 accessible-name assertions 覆蓋。
7. Claude 發現 Manager 入口斷言使用不存在的「員工管理」字串、Desktop
   只量 Dashboard、Safe Area 條件偏恆真、內容空白沒有量測證據。
   腳本改為正確比對「員工/帳號管理」等三個入口，逐主題逐頁量
   hierarchy／overflow，以 96px 間距上限承接已刪副標空間，並使用
   Chrome CDP 實際注入 safe-area insets。

以上只調整前端 Accessibility／Presentation 與對應測試；沒有 Backend、
API、schema、Business Logic、Workflow、權限或 dependency 變更。
