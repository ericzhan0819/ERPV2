## 正式能力

```text
Admin 建立員工／重設密碼
→ must_change_password=true
→ 員工以 Email 與預設密碼登入
→ 後端與前端強制修改密碼
→ 可在我的帳號設定 username
→ 後續可用 username 或 Email 登入
```

- username 為 nullable、3～30 字元、正規化小寫、case-insensitive unique。
- username／Email 是同一 User 的 alias，共用 canonical Rate Limiter。
- self profile 只能改 name／username；self password 必須驗目前密碼、confirmation 且不能沿用舊密碼。
- Email、role、is_admin、is_active 與員工欄位不能由 self API 修改。
- 密碼不進 Resource、Audit 或一般 log。
- 系統識別集中在 `frontend/src/config/app.ts`，仍是 source-controlled config。

## 部署與相容性

- 部署需執行一般 `php artisan migrate`；migration 不回填 username，也不把既有 User 設為待改密碼。
- 既有帳號升級後保持 `username=null`、`must_change_password=false`，可繼續用 Email 登入。
- 前端登入 payload 已由 `email` 改為 `login`；舊 client 若仍傳 `email` 會取得 422，需與 v1.5 前端一併部署。
- 調整公司／系統名稱只修改 `frontend/src/config/app.ts` 並重新 build；沒有線上設定頁。
- 認證只支援 Sanctum SPA cookie／Session，不支援 Bearer token。

## 禁止擴張

v1.5 不包含自助註冊、忘記密碼 Email、Email 驗證、MFA／SSO、裝置／Session 管理、Database settings、線上系統設定、多公司品牌或 Theme server-side 個人設定。後續需求必須另立企劃與 PLAN。
