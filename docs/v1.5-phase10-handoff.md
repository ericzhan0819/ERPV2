## 正式契約

### Login

- state 與 payload 均使用 `login`，input type 為 `text`，允許 username 或 Email。
- Login input 使用 `autocomplete="username"`；密碼使用 `autocomplete="current-password"`。
- 登入成功回傳的完整 User 是導向依據：flag=true 進 `/change-password`，flag=false 進 `/dashboard`。
- 既有 API 通用錯誤與 429 訊息仍直接顯示；network／非標準錯誤使用安全 fallback。
- Login title 與 subtitle 取自 app config，不再由元件直接硬編碼。

### 強制修改密碼

- 表單只送出 `current_password`、`password`、`password_confirmation`。
- 目前密碼使用 `current-password` autocomplete；新密碼與確認欄使用 `new-password`。
- 前端先阻擋明確的 confirmation 不一致；後端 422 欄位錯誤回到對應欄位，輸入值不會因失敗清空。
- 只有 self-password API 成功並由 Auth Context 接受同一 User 的完整回應後才進 Dashboard；失敗時維持強制頁。
- 成功後後端回傳 flag=false，Auth Context 隨完整 User 更新，因此既有 Protected Route 不會形成 redirect loop。
- 送出期間所有欄位與兩個動作均 disabled；不會重複送出或在送出中登出。

### Session 失效

- Axios request interceptor 會把 `AUTH_SESSION_VERSION_KEY` 的當下值蓋印到 request config；response interceptor 只讓具備 generation 的 HTTP 401 發出 module-private Session invalidated event。
- Auth Provider 只在 logout 狀態為 idle，且 request generation 等於目前 generation 時接受失效事件；較舊的 bootstrap `/api/me` 或其他過期 request 之 401 不得清除較新的登入 User。
- 有效失效事件會清除目前 Context，並寫入既有 `LOGOUT_STATE_KEY=completed`，讓其他分頁沿用既有 storage listener 同步關閉已渲染的營運畫面。
- logout pending／blocked 的安全畫面不會被 401 事件覆蓋。
- Authenticated route 在 User 清除後由既有 Protected Route 導回 Login。
- 強制修改密碼請求本身收到 401 時亦明確 replace 導向 Login。
- Self-password API 已回 200、但完整 User 因 Context 已切換而被拒收時，呼叫端辨識 `StaleCurrentUserResponseError` 為「後端已完成、前端回應過期」，改以「密碼已更新，請使用新密碼重新登入」提示導向 Login，不會誤報修改失敗。
- Self-password API 成功且完整 User 被目前 Context 接受後，會配合後端 Session ID regenerate 更新 auth session generation；修改密碼前送出的舊 request 之 401 不得再清除新 Session。
- admin reset 的舊 Session 不會被誤判成 `PASSWORD_CHANGE_REQUIRED`；使用者需以新預設密碼重新登入，再依登入回應 flag 進強制頁。

## Adversarial Review Follow-up

2026-07-27 收到 1 項 Medium 與 2 項 Low findings，逐項回到實際控制流查證後均確認有效並修正：

- F1 有效：原全域 401 listener 沒有 `meRequestValidRef` 的等價 generation 守衛。Bootstrap `/api/me` 若在新登入成功後才回 401，Promise catch 雖會正確忽略，interceptor listener 卻會先清掉新 User。現在每個 request 都蓋印既有 auth session version；只有 request 與目前 generation 相同時才接受 401。已補 null bootstrap、相同 generation 與舊 generation 直接測試。
- F2 有效：Self-password API 200 後若完整 User 因 Context 已切換而被拒收，原頁面會把 `StaleCurrentUserResponseError` 誤顯示為「修改失敗」，但後端密碼其實已 commit。現在該例外固定導向 Login 並顯示「密碼已更新，請使用新密碼重新登入」，不再讓使用者拿舊密碼反覆重試。
- F3 有效：原有效 401 只清目前分頁，其他沒有再發 request 的分頁會繼續顯示已渲染資料。現在 generation 守衛通過後才寫入既有 `LOGOUT_STATE_KEY=completed`，重用既有 storage listener 同步清除其他分頁；過期 401 無權寫入 marker。
